# Phase 0 唯一 on 机制规格：BPW（Budget-matched Persistence-Weighted densification）

**日期**：2026-10-27
**状态**：设计锁定（P3-D2-005 / P3-D1-003 / P3-D1-004），未实现、未跑 GPU
**上位约束**：`paper3/PREREGISTRATION.md` §3.1（正式判据，单一事实源）、`DISCIPLINE.md` 渐进阶梯、
审计 `audit_legacy_densification_2026-10-27.md` §4

---

## 1. 一句话定义

**在不增加任何高斯预算的前提下，把每个 densify 事件的 k 个新增名额，从"梯度最大者"改判给"持久性最高者"。**

一句话检验：如果效果来自"更多高斯"，本机制必输（因为 k 与 off 逐事件相等）；
如果效果来自"长在对的地方"，本机制才可能赢。

## 2. 为什么是这个机制（而不是 A4/B1 复刻）

审计已确认三条历史事实：

1. A4（grad 0.0002→0.0001，percent_dense 0.01→0.02）两次复现 ATE −29%，但代价是高斯数
   2.1×–6.5× 与 PSNR 下降。**增益与剂量完全混杂**，无法区分"更多"与"更对"。
2. 深度符号账本（B2d）是唯一过安慰剂门禁的信号（41.9 vs 安慰剂 49.0，2/3 seed），
   但它仍以"剂量保守"收场——信号对了，预算没解决，绝对值平庸（41.9cm）。
3. 现有代码已经具备 per-Gaussian 梯度阈值 / percent_dense 向量通路
   （`gaussian_model.py:1295+` 的 `densify_and_split` / `densify_and_clone`），
   且 `SelectiveDensification.enabled: false` 为默认值 —— **机制可以只靠传向量实现，
   不需要改动核心模型文件**。

BPW 的设计意图正是修补第 1 条的混杂：**把剂量做成硬约束而非自由变量**。

## 3. 形式定义

在单个 densify 事件 t：

- 令 `accum_i` 为高斯 i 的累计位置梯度（现有量 `xyz_gradient_accum`）。
- 令 `p_i ≥ 0` 为高斯 i 的**持久性**，直接取 `denom_i`（每次该高斯被渲染命中即 +1，
  且**每次 densify 事件后重置为 0**）。因此 p_i 的语义是
  **"自上次生长以来被观测到的次数"**，不是生命周期内的总观测次数。
  这个定义是有意的：它衡量的是"这颗高斯近期是否持续被支持"，而不是"它有多老"——
  后者会让早期出生的高斯无条件获得排序优势。
  **不使用** `static_obs_count`：该字段仅在 `AlphaLifecycle.mode != off` 时更新，
  默认配置下恒为 0（2026-10-28 实测会导致选择器退化为索引序）。
- 令 `τ_base` 为 off 臂的标量梯度阈值（`opt_params.densify_grad_threshold`，默认 2e-4）。
- 令 `τ_lo < τ_base` 为放宽阈值。**先验锁定 τ_lo = 0.5·τ_base**（不逐序列调、不看结果改）。
- **先验锁定 p0 = 8.0 次观测**。p0 是 e_i 里的收缩先验：p_i = p0 时得分恰为平均梯度的一半。
  取 8.0 与 window_size=8 对齐——在最小可观测窗口内，只被看到少数几次的高斯不会仅凭
  几帧的偶然大梯度挤掉长期稳定支持的高斯。**该值在看到任何 Phase 0 结果前写死，跑后不得调整**。
  若需要敏感性分析，只能在 Phase 1 作为独立预设臂（p0 ∈ {4, 8, 16}）报告，且不得用于改写
  Phase 0 判决。

定义证据分：

```
e_i = accum_i / (denom_i + p0)        # 等价于 mean_grad_i · p_i/(p_i+p0)
```

候选池与预算（**按新建高斯数计，不按源点数计**）：

```
P0     = { i : g_i ≥ τ_base }              # off 的选中集
P      = { i : g_i ≥ τ_lo }                # 候选池（τ_lo = 0.5·τ_base，超集）
budget = |P0|                               # 固定 = off 本事件选中的源点数
S      = 在 P 内按 e_i 降序取前 |budget| 个

# 注：clone 净增 +1（父点保留，新增 1 个子点）；
#     split 净增 +1（父点被 2 个子点替换，2-1=1）。
#     两分支净增均为 1，故 |S| == budget 即保证新增高斯数与 off 严格相等。
#     早期草稿曾用 cost(1/2) 加权，已废弃：那会让预算偏离而不是匹配。
```

> **为什么池必须比 off 宽**：若 P 恰等于 P0，我机制能选的就只有 off 已经全选的集合，
> greedy 会照单全收，BPW 退化为 exact no-op。机制要改变的是"同样预算下选谁"，
> 因此池放宽到 τ_lo、预算仍锁在 off 的 budget。差额 leftover（<1 个 clone 的量）记 log。
> **对照 placebo = 同池、同预算、把 e_i 确定性置换后排序**——两者共享池与预算，
> 只差排序键，这才是"排序信号"的独立检验。

> **预算匹配的正确口径（2026-10-28 审计修订）**：`budget` 是**逐事件的反事实量**，
> 即「在参考臂同一事件、同一前置地图状态下，会被选中的源点数」，快照取自
> **本事件开始前**的 `xyz_gradient_accum / denom`。它不是、也不可能是
> 「各臂最终 `online_num_gaussians` 相等」。理由：两臂一旦选了不同的点致密化，地图几何
> 与下一次事件的梯度分布就不同了，下一事件的 `k` 自然分叉——这正是机制在起作用，
> 不是实现缺陷。**因此「三臂最终高斯数相对差 ≤ 2%」不能作为验收判据**（结构性不可达）；
> 它是对训练动态的过强约束，只有引入与机制无关的全局数量上限才能满足，而那个上限
> 本身会污染归因。
>
> **替代的、可机械判定的验收条件（P0-A′）**：
> 1. **首事件 k 相等**：三臂在第一个 densify 事件的 `budget` 完全相同
>    （这是纯快照量，没有历史漂移，可精确比较）；
> 2. **逐事件 k 序列与参考臂的 `P0` 序列相等**：即每个事件的 `budget` 等于
>    参考臂同事件按标量 τ_base 得到的 `|P0|`（由 log 逐事件核对，允许为 0）；
> 3. **总计数作为报告项，不作为通过门槛**：记录 off/on/negctl 的最终高斯数
>    与其比值，供论文如实陈述剂量差异，但不据此判 PASS/FAIL。

下发向量（现有接口）：

```
grad_threshold_vec[i] = -1.0,  i ∈ S     # 任何非负梯度都通过
grad_threshold_vec[i] = +inf,  其他
percent_dense_vec[i]  = pd_default (0.01), 全部
```

> **依赖（2026-10-28 修订）：不使用 `static_obs_count`。**
> 早先草稿把持久性定为 `static_obs_count`，但该字段**只由 `AlphaLifecycle` 路径维护**
> （`utils/slam_backend.py` 的 `_alpha_lifecycle_step`），默认配置下恒为 0。实测后果：
> 所有 p_i = 0 → e_i 全为 0 → top-k 退化为索引序，机制静默空转（首轮冒烟日志
> `mean_p=1.00 fallback=1`）。
> 现改用 `denom`：它由 `add_densification_stats` 无条件累加、每次 densify 后归零，
> 语义正是"自上次生长以来被看到的次数"，无需任何额外开关。
> 仍保留兜底：若 `denom.max() == 0`（首次事件），退回按原始梯度排序并记 `fallback=1`。

> **修正（2026-10-27，实现期发现）**：首版规格曾写「选中者用 aggressive
> percent_dense = 0.02」。那是错的：percent_dense 决定 clone/split 的分界
> （尺度 ≤ bound 走 clone，> bound 走 split），把它抬到 0.02 会让更多点走 clone
> 分支，从而改变每个候选的创建成本（1 或 2），**预算就不再逐事件相等**。
> 因此 percent_dense 全程保持 base 值，只有阈值参与重排。这是严格 k 的必要条件。

由于现有 `densify_and_clone/split` 中 `grad_norm >= threshold_vec` 与 scale 判据是
**AND 关系且二分支互补**（clone 走 `scale <= bound`，split 走 `scale > bound`），
所以「`threshold = -1` 于 S、`+inf` 于其余」在数学上保证**恰好 S 内被致密化**。

## 4. 三个比较臂

| 臂 | 定义 | 作用 |
|---|---|---|
| `off` | 现有默认致密化（标量 τ_base / pd 0.01） | 基线 |
| `on` (BPW) | 上述严格 k + 持久性排序 | 主臂 |
| `negctl` | 同 k、同候选池 P、但 `e_i` 做确定性置换（固定 seed） | 区分"预算匹配本身"与"持久性排序的信息量" |

**关键**：`negctl` 与 `on` 的新增数逐事件完全相等。因此
`on vs negctl` 的差值只能归因于**排序信号**，不能归因于剂量。这是本设计相对历史两族的
唯一结构性改进。

## 5. 主场景与判据

### 5.1 战场（依 P3-D1-003）

标准子集 r33 baseline 实测（3 seed）：

| 序列 | baseline ATE (cm, mean±sd) | 判定用途 |
|---|---:|---|
| balloon | 3.25±0.07 | **易序列不退化门**（已有余量，任何机制都不该弄坏） |
| crowd | 1.53±0.02 | 同上 |
| crowd3 | 1.53±0.02 | 同上 |
| crowd2 | 2.26±0.32 | 同上 |
| balloon2 | 5.48±0.27 | 轻微超线，观察 |
| **person_tracking** | **11.31±0.70** | **唯一有 headroom 的主战场** |
| person_tracking2 | 10.40±0.28 | 次战场 |

**明确记录**：「绝对 ATE ≤5cm，目标 2–3cm」在 5/7 序列上 off 臂已达成，
**该门槛在易序列上没有判别力**。因此 Phase 0 不使用它作为主判据，
而把它保留为 Phase 2 在全 9 子集上的验收线。

### 5.2 Phase 0 判据（跑前锁定，机械可判）

**主判据 P0-A（机制生效）**：
- **剂量硬约束（逐事件口径，2026-10-28 修订）**：每个 densify 事件上，
  `on` 与 `negctl` 的 `budget` 彼此相等，且等于参考臂（off）在该事件的 `|P0|`。
  首事件必须完全相等（无历史漂移）；后续事件的比较以「同事件、同前置状态」为准。
  **不再**使用「三端最终高斯数相对差 ≤ 2%」—— 见 §5.3。
- 两者在 ≥2 个主场景上的 ATE 差方向一致且 `|Δ| > 噪声地板`。

**噪声地板（本文档锁定）**：0.62 cm（跨批实测上界，r33 报告区间 0.18–0.62 cm）。
单 seed 差值必须报 seed 内极差作为辅助；单 seed 结论一律标「方向性」。

**主判据 P0-B（不退化）**：`on` 在 balloon / crowd / crowd2 / crowd3 上
`ΔATE ≤ +0.62cm`（即不超过噪声地板）。

> **注（2026-10-27 对齐）**：本节与 `PREREGISTRATION.md` §3.1 的 P0-A/B/C 是同一套判据的两种陈述。
> §3.1 为单一事实源；本节的 P0-A 对应 §3.1 P0-A，本节的 P0-B 对应 §3.1 P0-B+P0-C。
> 若出现歧义，以 §3.1 为准。

### 5.3 为什么弃用「三端最终高斯数相对差 ≤ 2%」（2026-10-28 审计）

该判据在原理上不可达，不是实现没做好：

1. **它是内生量，不是控制变量**。`budget = |{g_i ≥ τ_base}|` 取自**当前地图状态**
   的梯度统计。两臂一旦选了不同的点去致密化，点的位置/尺度/密度就不同，下一次
   事件的梯度分布随之不同，`k` 必然分叉。这是机制在起作用，正是我们要测的东西。
2. **强行拉平会引入混杂**。要让三端最终计数相等，只能加一个与排序机制无关的
   全局数量上限/补偿器——那个补偿器本身会改变地图几何，归因就不再干净。
3. **正确的检验是反事实的，不是终态的**。要问的是「同一事件、同一前置状态下，
   on 会不会选同样多、但不同的点」，这由每事件 log 的 `budget` 直接回答。

⇒ 因此 Phase 0 的剂量判据改为：**首事件 k 完全相等 + 逐事件 k 等于参考臂 `|P0|`**。
最终高斯数作为**报告项**记录（论文需如实陈述剂量差异），不参与 PASS/FAIL。

> 附：2026-10-28 修复前，三端首事件因随机流未对齐而不同（pool 4219 vs 4184）。
> 对齐 `rng_sequence` 后首事件一致（4186/2187），但最终计数仍为
> 26843 / 29548 / 20867 —— 这恰是第 1 点的实证。

**失败处理（依 P3-D1-001 阶梯纪律）**：
- P0-A 不过（on ≈ negctl）⇒ 持久性排序无信息量，机制方向关闭，记入 NOTES 已排除方向；
- P0-C 不过（易序列退化 > 噪声地板）⇒ 判「不退化门失败」，机制方向关闭，**不得**靠调 p0/τ_lo 抢救
  （这两个值已在 §3 先验锁定，跑后调整即构成事后选参）；
- P0-B 不过（未能优于 placebo）但 P0-C 通过 ⇒ 记「预算匹配有效、持久性排序无信息量」这一
  有界结论，可进入 Phase 1 作为对照臂保留；
- 若失败源于**实现缺陷**（如 k 与 off 失配、置换未固定 seed），按阶梯纪律允许一次修复后按
  **同一判据**重跑——这是修 bug、不是调参，须在 manifest 中记录缺陷描述与修复 commit。
- 全部通过 ⇒ 进入 Phase 1（加 2–3 个不同场景类型，每配置单 seed）。

## 6. 实现计划（feature 分支，默认关闭）

1. `utils/selective_densification.py` 增加 `signal: "persistence_budget"` 分支，
   复用现有 `compute_per_gaussian_knobs` 返回签名（返回两个向量），
   在 backend 内部计算 k（需要与 off 同事件同判据的梯度统计）。
2. 关键约束：k 的计算必须与 off 的 `densify_and_prune` 使用**同一份** `grads` 快照，
   否则 k 与 off 失配。做法：在调用 `densify_and_prune` 前，用同一个
   `xyz_gradient_accum/denom` 计算 `k = (grads >= τ_base).sum()`，再据此构造向量。
3. `configs/densification/` 下新增三份配置：`bpw_off.yaml`（等价现有默认）、
   `bpw_on.yaml`、`bpw_negctl.yaml`（置换 seed 固定）。
4. 单测（`tests/densification/`）：
   - `on` 与 `off` 在同一 seed 下新增高斯数逐事件相等（核心不变量）；
   - `negctl` 与 `on` 的新增数也逐事件相等（保证只在排序上不同）；
   - `enabled: false` 时与主线逐位一致（现有承诺的回归保护）。
5. 2–4 run Phase 0：主场景 person_tracking（1 seed，主） + balloon（1 seed，不退化门）；
   canonical 掩码口径，static_bg_mask_subdir 与现役一致。
6. 交付三件套：跟踪表、渲染表、原图/渲染对照（`render_compare.py`）。

## 7. 风险与预先承认的边界

- **k 的信号尺度风险**：p_i 用累计观测计数，长寿命高斯（背景）天然 p_i 大，
  可能把名额推给静态背景而非动态区。这是有意为之的对照——若结果如此，
  说明"持久性"在当前定义下等价于"被看得多"，机制退化为静态优先，需如实报告。
- **k 匹配的粒度**：逐事件匹配在 evaluate 阶段可能因 prune 时机不同而产生计数漂移；
  单测里以「同一 seed、同一事件索引」对齐，不跨事件比较。
- **单 seed 局限**：Phase 0 只有 1 seed，ATE 结论只能作方向性；任何 >噪声地板 的
  声称都必须在 Phase 1 用 2 seed 复核后才能写入论文。

## 8. 与历史的两条红线

1. **不得**把 A4/B1 的 31.36 / 32.88 cm 当作本机制的基线或结果——那是不同剂量。
2. **不得**把本机制在 moving_obstructing_box 上的结果写成论文 3 新结果——该战场已判无效。
