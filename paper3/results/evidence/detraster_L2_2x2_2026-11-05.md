# det-raster 2×2 决定性实验：单线程下 det-ON 达成逐位可判（2026-11-05）

**这一份是本轮的核心结果。** L1 判决（R-infeasible）的失败**归因被修正**：
不是 det-raster 无效，而是**判据在 async 架构下不可达**。

---

## 一、2×2 设计

唯一两个变量：`single_thread`（调度）× `Rasterizer.deterministic_backward`（算子）。

配置：`person_tracking`，seed 0，40 帧，每格 2 run（同 config 同 seed），
确定性套件全开（`use_deterministic_algorithms(True, warn_only=False)` +
`CUBLAS_WORKSPACE_CONFIG=:4096:8` + `PYTHONHASHSEED=0`（env 预置）+ cudnn/TF32 关），
单卡串行，全 rc=0。

|  | **det OFF** | **det ON** |
|---|---|---|
| **async**（默认） | 9/9 件 DIFF | 9/9 件 DIFF |
| **single_thread** | **关键数值列 DIFF** | **逐位一致** ✔ |

## 四、结论（三条，都可独立引用）

1. **det-raster 是必要且（在固定调度下）充分的。**
   2×2 的其余三格全部不可复现，只有「单线程 + det-ON」这一格逐位一致。

2. **L1 失败的真正原因是判据与架构不匹配，不是机制无效。**
   async 模式下 backend 在队列空时无上限地跑 `map()`（`slam_backend.py:2105-2112`），
   每个 KF 之间跑多少迭代由墙上时钟决定 —— 实测同 20 帧两次跑分别是
   **735 vs 700 个不同 iteration**。这在**任何**算子实现下都会导致终端文件不同。
   ⇒ 原判据「40 帧 ×2 逐位一致」在 async 下**结构上不可达**。

3. **臂级可判性的条件被明确成文**：
   `single_thread=true`（前端 `Training.single_thread` **且** 后端 `Dataset.single_thread`）
   + `Rasterizer.deterministic_backward=true` + 确定性套件 → 逐位可复现。

## 五、必须同时说明的代价与边界

- **`single_thread` 不是主线配置。** 它让后端不再自由跑，性能与行为都不同
   （本次 ATE 1.168 vs async 的 1.177；gaussian 数 19771 vs 25976）。
   ⇒ **单线程读数不能直接当主线读数用**，它是**仪器模式**，不是部署模式。
- 因此本文档建立的是「**测量仪器**在固定调度下可逐位复现」，
  **不**宣称「主线的 async 配置也可复现」。后者是架构问题，不是本次机制的范围。
- 40 帧单线程 run 的 `num_gaussians`=19771 与 async 的 25976 差异较大，
  说明调度本身显著影响建图动态 —— 这是既有事实，不是本次引入的。

## 六、踩到的坑（登记）

**`single_thread` 有两个不同的 key，读不同的 config 段**：

```python
# utils/slam_frontend.py:357
self.single_thread = self.config["Training"]["single_thread"]
# utils/slam_backend.py:317-321
self.single_thread = (self.config["Dataset"]["single_thread"]
                      if "single_thread" in self.config["Dataset"] else False)
```

只设 `Training.single_thread: true` ⇒ **后端仍是 async**，前端却在等后端
（等待条件 `if self.single_thread and self.requested_keyframe > 0: continue`）。
本轮前两次「单线程」测试就是这样，导致结论被误导了一轮。**必须两处都设。**

## 七、对 P3-D2-028 判决的修订建议

原判决「R-infeasible（部分否证）」应改为：

> **R-feasible-under-fixed-schedule（条件成立）**：
> det-raster 在 `single_thread` 固定调度下使 40 帧 ×2 逐位一致（5 个纯数值判据件
> md5 相同 + 全部非元数据列相同 + KF 模式相同）；
> 但 async 主线配置下不可达 —— 原因在调度架构，不在算子。
> 是否把 `single_thread` 纳入机制研究的标准仪器配置，属 **D2 拍板**。
