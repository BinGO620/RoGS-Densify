## 选项甲：prune 侧干预（新机制，需新 prereg）

**为什么**：现有全部机制（BPW/MaskStat/MinObsGate）都在 **densify 侧**。
prune 侧从未被触碰。已知线索：夜间 itr 扫描里 `Pruned N lineage(s): removed M`
的 M 随 itr 大幅变化，说明 prune 行为与优化量强耦合。

**候选机制（需选定一个，不并行）**：
- 甲-1「观测支撑的时间衰减」：prune 判据除 opacity 外加入「最近 K 次渲染中是否被命中」，
  长期不被看到的基元优先删（而非仅按 opacity 低）。
- 甲-2「动态残差豁免」：prune 前检查该基元是否处于高残差区（动态物体旁），
  是则暂缓一次（避免动态带来的错误基元在物走后无人清理 / 或反之加速清理）。

**成本**：实现 1-2h + 仪器口径 n=3 全长 6 run ≈ 4.5h。
**判力**：与 MinObsGate 同量级风险 —— 门槛类干预对 seed 敏感。

## 选项乙：事件级配对判读（E2，框架已有但从未跑）

**为什么**：框架 v2 的 E2（逐事件配对，`prereg_device_robust_estimand` §E2）**从未
真正执行过**。它要求的工件（逐 densify 事件机制输入量落盘 + 逐事件装置地板）
都还没建。这条路的产出是**判读能力**而非机制结论。

**必须做的前置（E2 前置链，全部未做）**：
1. 两臂都要有逐事件机制输入量落盘（trace CSV，config 门默认关）；
2. 逐事件装置地板 = **同确定性状态 + 同事件载体**下同臂重跑 ≥3 样本；
3. 现有 off 臂 3 样本是 det-OFF 且无逐事件落盘 ⇒ **不得**充当地板（框架明文禁止）。

**成本**：工件建设 ~3h + 地板测量（3 run × 2 臂）≈ 3h + 新机制批 4.5h。
**判力**：比臂级 ATE 更细，能判「机制是否真的改变了 densify 决策」——
即使 ATE 无差异，也能证明机制在工作（或证明它没工作）。

## 我的建议：**先乙，后甲**

理由：
1. **乙的产出是永久的判读能力**，不依赖某个机制是否有效。即使所有机制都失败，
   E2 工件 + 地板让"机制没工作"和"机制工作了但 ATE 没变"能区分开 ——
   这是论文 3 目前最大的盲区（现在只能说"ATE 没差异"）。
2. **甲是最后一次机制机会**，但没有 E2 的话，甲的失败会重复 MinObsGate 的困境
   （不知道是机制无效还是判力不足）。
3. 丙随时可做（0 GPU），不是竞争关系。

**若乙完成后甲仍失败** ⇒ 转丙，并把研究内容三的定位从「机制贡献」改写为
「测量学贡献 + 机制边界刻画」—— 这是一个需要用户拍板的**定位变更**，
不是我能自裁的范围。
